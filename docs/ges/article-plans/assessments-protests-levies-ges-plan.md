## Editorial Diagnosis

The source document is accurate and useful, but the first conversion plan still treated too many source concepts as equal article sections. The result risked becoming a visualized white paper: correct, heavily diagrammed, but still shaped around assessment administration instead of the homeowner's next question.

The revised article should follow a homeowner's natural question sequence:

```text
What did I receive?
Is this a tax bill?
What facts should I check first?
How was the value built?
How does the county test fairness?
What can I do if my parcel looks wrong?
How does value become taxes?
```

The core reader journey:

```text
Notice arrives -> check the facts -> understand the value -> distinguish group fairness from parcel review -> see how value becomes taxes
```

The article should feel like a guided learning path. It should not feel like a short course in appraisal methodology.

## Five-Act Article Architecture

### Act 1 - The Notice Moment

Primary reader questions:

- What did I just receive?
- Is this a tax bill?
- Who handles which question?

Purpose: Orient the reader before terminology accumulates. The reader should leave this act understanding that a valuation notice is a value-side document, not the final tax bill.

Required anchor visuals:

- Annotated valuation notice.
- Three-lane system map.
- Role-responsibility diagram.

Required memory anchor:

> A valuation notice is not a tax bill.

Narrative flow:

1. Start with the notice moment.
2. Identify the immediate confusion: value, protest timing, and tax impact are connected but separate.
3. Show the three lanes: value, review, taxes.
4. Show who owns each kind of question.

Implementation recommendation:

- Build as the article's orientation act.
- Use the annotated notice as the first major visual.
- Follow with a compact three-lane system map that can reappear as a small progress cue later in the article.
- Keep the role diagram practical: "ask this office about..." rather than a government-org chart.

### Act 2 - The Value Number

Primary reader questions:

- What does assessed value mean?
- Why does January 1 matter?
- What facts should I check first?
- Is my concern about the record or the value?

Purpose: Move record verification earlier. Before the reader learns appraisal methodology, they should know what facts to inspect and how to separate factual issues from valuation disagreement.

Required anchor visual:

- Property record checklist.

Required distinctions:

- Record issue vs value issue.
- Factual correction vs formal valuation protest.

Required margin insight:

> Check facts before arguing conclusions.

Required memory anchor:

> January 1 is the snapshot date.

Narrative flow:

1. Define assessed value as a market-value opinion for taxation.
2. Explain January 1 as the snapshot date.
3. Give the reader a record-check checklist: parcel identity, land, dwelling size, quality/condition, outbuildings, removed structures, classification, and obvious permit/update issues.
4. Use a decision card to split record issues from value issues.

Implementation recommendation:

- This act should contain the first concrete task in the article.
- Link directly to Guided Parcel Review after the checklist.
- Use the record vs value distinction as a decision tree, but keep the full protest process for Act 4.
- Add a practical note that correcting a record fact does not automatically determine final value, but it improves the basis for review.

### Act 3 - How the Value Is Built

Primary reader questions:

- How was this value built?
- What does land have to do with the total?
- What are improvements?
- How do sales, cost, income, depreciation, data sources, CAMA, and mass appraisal fit without becoming separate lessons?

Purpose: Condense the prior valuation-method sections into one guided interactive module. The article should teach enough recognition for the reader to understand the value, not train the reader to be an appraiser.

Required anchor visual:

- Value build-up diagram.

Required guided component:

`Value Builder`

Tabs/cards inside the component:

- Land.
- Improvements.
- Sales approach.
- Cost approach.
- Income approach.
- Replacement cost.
- Depreciation.
- CAMA/mass appraisal.
- Data sources.

Required micrographics inside the module:

- Land + improvements equation.
- Common meaning vs appraisal meaning for "improvements."
- Replacement cost -> depreciation -> indicated value mini-flow.
- One parcel vs many parcels mini-flow for mass appraisal.

Required memory anchors:

> Land plus improvements becomes the starting value.

> Mass appraisal values groups. Protests review parcels.

Narrative flow:

1. Start with the simplest mental model: land plus improvements.
2. Explain that different property types lean on different valuation approaches.
3. Keep sales, cost, and income as cards, not sections.
4. Use the cost approach as the residential example, but keep the explanation bounded.
5. Explain CAMA/mass appraisal as the consistency system for many properties.
6. Close by returning to the property record: a model can be consistent and still need a corrected record.

Implementation recommendation:

- This should be one substantial interactive or progressive-disclosure component, not eight sections.
- The default state should show a simple build-up diagram. Tabs/cards should let curious readers inspect parts without forcing every reader through every detail.
- Keep all advanced method language short and sourced.
- Use a "for most homeowners" framing, but avoid implying the cost approach is the only residential method.

### Act 4 - How Fairness Is Checked and Challenged

Primary reader questions:

- Are similar properties being treated similarly?
- What is equalization?
- What is the difference between countywide fairness and my parcel review?
- What can I do if my parcel looks wrong?

Purpose: Teach equalization first as group fairness, then protest as parcel-specific review. The reader should understand that countywide metrics can reveal system patterns but do not automatically prove one parcel's value.

Required anchor visuals:

- Equalization vs protest comparison.
- Protest path flowchart.

Required optional detail:

Expandable component labelled:

```text
For readers who want the metrics
```

Include in optional detail:

- COD as a measure of spread/dispersion.
- PRD as a measure of vertical equity/tilt.
- Link or source note to IAAO ratio-study standards.

Required cross-link:

- Before You Walk Into a Property Protest.

Required memory anchor:

> Equalization compares many properties. A protest reviews one.

Narrative flow:

1. Ask the plain-language fairness question: are similar properties being treated similarly?
2. Explain equalization as group review.
3. Explain why sales and statistics help test group performance.
4. Keep COD/PRD optional.
5. Contrast equalization with protest: group patterns vs parcel evidence.
6. Show the protest path: file with County Clerk, possible referee, BOE decision, possible TERC appeal.
7. Close with the short calendar pressure: the protest window is short because the tax calendar keeps moving.

Implementation recommendation:

- Do not make COD/PRD visible as headline concepts.
- Use the equalization/protest comparison as the teaching center of the act.
- Make the protest path print-safe, because this act is likely to be used as a reference.
- Add a continuation card to the protest evidence article before moving into taxes.

### Act 5 - How Value Becomes Taxes

Primary reader questions:

- How does assessed value become a tax bill?
- Why can my value change without my taxes changing in the same way?
- Where does the money go?
- What should I remember about the whole year?

Purpose: Sharpen the separation between value and taxes. The reader should finish with a durable model of value share, budget need, levy rate, and overlapping taxing authorities.

Required anchor visuals:

- Value-budget-levy-tax flow.
- Year-at-a-glance strip.

Conditional visual:

- Levy distribution visual only if supported by real local data.

Required memory anchors:

> Assessments estimate value. Levies distribute budgets.

> A higher value does not automatically mean the same tax increase.

Required teaching sequence:

1. Assessments distribute value share.
2. Budgets create revenue need.
3. Levies translate that need into rates.
4. Tax bills reflect overlapping taxing authorities.

Narrative flow:

1. Introduce value as the base for distributing cost.
2. Explain that taxing subdivisions set budgets/tax requests.
3. Explain levy as the rate needed to distribute those requests across taxable value.
4. Show why levy rates may move when the value base moves.
5. Show overlapping taxing authorities only with sourced data.
6. End with a year-at-a-glance strip that returns to the notice and closes the loop.

Implementation recommendation:

- Keep this act separate from protest. The reader should feel the handoff from value review into public budgeting and levy action.
- Use scenario cards for "values up, budget stable" and "values down, budget stable."
- Do not present unsourced levy distribution percentages. If real local data is not ready, replace with a generic authority stack and defer percentages to the future explorer.
